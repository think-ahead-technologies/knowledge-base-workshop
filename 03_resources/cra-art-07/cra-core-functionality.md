# CRA core functionality - classification key

Art. 7(1) ties the "important" status to the "Kernfunktionen" of an Annex III
category. The page reproduces the EU Commission guidance of 27 July 2026
(C(2026) 5252 final), section 6.1 "Kernfunktionalität", which is non-binding
(only the CJEU interprets the CRA bindingly):

- Whether a product is important (Annex III) or critical (Annex IV) is decided
  solely by its core functionality - the main features without which it could not
  fulfil its purpose. Ancillary features and integrated components do not change
  the classification; each product has exactly one core functionality, to be named
  clearly in the technical documentation.
- Integration is not classification: a smartphone with an integrated operating
  system does not have the core functionality of an operating system (example 58).
- Products clearly exceeding or falling short of a category are outside it: SOAR
  software is not a SIEM (example 59); simple log collectors without correlation
  are not either (example 60).
- No classification by marketing: contradictions between marketing material, user
  instructions and technical documentation must not be used to avoid the stricter
  procedure.
- Separately marketed modules of a product are each classified on their own
  (example 61: security suite with SIEM, IDS and analytics modules).
- Technical descriptions of the categories: Implementing Regulation (EU)
  2025/2392.

Practical advice on the page: write one sentence per product - "Without function
X the product does not fulfil its purpose" - and match only X against Annex
III/IV, keeping marketing, manual and technical documentation consistent. The FAQ
also points to recital 45 for the core-functionality logic.
